# codex-capacity-retry

[中文文档](README.zh-CN.md)

A local, transparent retry proxy for the [OpenAI Codex CLI](https://github.com/openai/codex). It automatically retries transient “Selected model is at capacity” failures while preserving Codex’s streaming experience.

~~~
Codex CLI ──► 127.0.0.1:8317 ──► https://chatgpt.com/backend-api/codex
                    │
                    └─ retry overloads, relay normal SSE events
~~~

## Why it helps

Codex may stop after only a few client-side retries when ChatGPT is temporarily overloaded. This proxy handles the response shapes observed in production:

| Upstream response | Proxy behavior |
| --- | --- |
| HTTP <code>429</code> or <code>529</code> | Retry with <code>Retry-After</code> when provided. |
| HTTP <code>200</code> with an overload event before output | Hold structural SSE events, discard the failed stream, and retry transparently. |
| HTTP <code>200</code> with an overload event after output starts | Swallow the overload event and close the stream; Codex retries the network failure. |
| Other errors | Relay unchanged to Codex. |

Retryable markers include <code>server_is_overloaded</code>, <code>usage_limit_reached</code>, <code>model_at_capacity</code>, <code>service_unavailable</code>, and matching “at capacity” messages. Retry budget exhaustion is reported normally instead of hanging indefinitely.

## Requirements

- macOS (the installer uses <code>launchd</code>; the proxy itself also runs on Linux)
- Node.js 18 or newer
- Python 3 (used by the shell helpers)
- Codex CLI signed in with a ChatGPT account (<code>~/.codex/auth.json</code>)

No API key is required. Codex continues to attach its own OAuth credentials.

## Install

~~~bash
git clone https://github.com/Jason213/codex-capacity-retry.git
cd codex-capacity-retry
./install.sh
~~~

The installer copies the proxy to <code>~/.codex/capacity-retry-proxy/</code>, creates the user service <code>com.codex.capacity-retry-proxy</code>, backs up and updates <code>~/.codex/config.toml</code>, and installs <code>cx_proxy</code>/<code>cx_office</code> into <code>~/.local/bin</code>.

If ChatGPT is reachable only through a local network proxy, export <code>https_proxy</code> (and optionally <code>http_proxy</code>) before installing; the values are written to the service environment. To prepare files without starting <code>launchd</code>, use <code>SKIP_LAUNCHD=1 ./install.sh</code>.

Verify a new Codex session and inspect the log:

~~~bash
codex exec --skip-git-repo-check "Reply with exactly: OK"
tail -5 ~/.codex/capacity-retry-proxy/proxy.log
~~~

An entry such as <code>POST /backend-api/codex/responses -&gt; 200</code> confirms that the request reached the proxy.

## Switch modes

| Command | Effect |
| --- | --- |
| <code>cx_proxy</code> | Enable the service and route new Codex sessions through the retry proxy. |
| <code>cx_office</code> | Remove the custom provider and stop/disable the service for native direct access. |

Mode changes apply only to newly started Codex sessions.

## Configuration

Edit <code>~/Library/LaunchAgents/com.codex.capacity-retry-proxy.plist</code> and restart with <code>cx_office &amp;&amp; cx_proxy</code>:

| Variable | Default | Purpose |
| --- | ---: | --- |
| <code>PORT</code> | <code>8317</code> | Local listen port. Use <code>CODEX_RETRY_PORT=8318 ./install.sh</code> to change it consistently. |
| <code>MAX_ATTEMPTS</code> | <code>20</code> | Maximum attempts, including the initial request. |
| <code>BASE_DELAY_MS</code> | <code>3000</code> | Initial backoff delay in milliseconds. |
| <code>UPSTREAM</code> | <code>https://chatgpt.com</code> | Upstream origin; normally leave unchanged. |

Backoff doubles up to 30 seconds. A <code>Retry-After</code> value is honored up to 60 seconds.

## Troubleshooting

~~~bash
tail -f ~/.codex/capacity-retry-proxy/proxy.log
~~~

- <code>in-stream ... will retry</code>: a pre-output overload is being retried internally.
- <code>mid-stream capacity error swallowed</code>: Codex is expected to reconnect and retry.
- <code>capacity error but retry budget exhausted</code>: the final upstream error was returned.
- <code>stream read error</code> or <code>upstream error</code>: check ChatGPT reachability and any <code>https_proxy</code> setting.

After changing Node.js installations, rerun <code>./install.sh</code> so <code>launchd</code> gets the current executable path. If Codex reports a TOML parse error, restore the newest <code>~/.codex/config.toml.bak-*</code> backup.

## Linux

Run the proxy under your preferred supervisor and configure Codex’s provider manually:

~~~bash
mkdir -p ~/.codex/capacity-retry-proxy
cp proxy.mjs ~/.codex/capacity-retry-proxy/
PORT=8317 node ~/.codex/capacity-retry-proxy/proxy.mjs
~~~

Use the provider block generated by <code>bin/cx_proxy</code> as the basis for <code>~/.codex/config.toml</code>, then manage the process with <code>systemd</code> or another supervisor.

## Uninstall

~~~bash
./uninstall.sh
~~~

The script backs up <code>config.toml</code>, restores native Codex access, removes the <code>launchd</code> service, and deletes installed proxy files and switch commands.

## Security

The proxy binds only to <code>127.0.0.1</code> and forwards only to <code>https://chatgpt.com</code>. It does not parse or persist OAuth credentials. Treat <code>~/.codex/auth.json</code>, proxy environment values, headers, and logs as sensitive.
